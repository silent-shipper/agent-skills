# One-Pager

A one-pager is a structured, persuasive document written for decision-makers, not engineers. It earns approval by being clear, credible, and concise — not comprehensive. The goal is to be fully understood in under 3 minutes.

## Process

**1. Read references first — never guess at format**

Search the user's workspace (Notion, Drive, wherever they keep docs) for:
- The existing template for this document type
- 2–3 real examples from the same org
- A writing sample from the user themselves

Format mismatch kills credibility. Match section structure, heading style, and prose density of the existing docs exactly.

**2. Calibrate to the user's voice**

Find a writing sample and internalize it before writing anything. Ask yourself: how long are their sentences? Do they use bullet points or prose? How much do they explain vs. trust the reader? Write so it sounds like them, not you.

**3. Lead with the dream, not the features**

The objective/intro should sell the outcome, not describe the system.

| Weak | Strong |
|------|--------|
| "Build a market agent that runs on a VPS" | "Turn near.com from a swap interface into a daily-use financial co-pilot" |
| "Add email login to the app" | "Let any user onboard with just an email — no wallet required" |

**4. Business first, always**

Every section: lead with revenue, retention, positioning, or risk reduction. Features and implementation come after. Stakeholders approve things that make money or reduce cost.

**5. Strip AI slop ruthlessly**

Cut anything that matches these patterns:
- Hedges: "potentially", "could help to", "may provide value", "it's worth noting"
- Over-explanation: restating what a smart reader can infer
- Padding: making the same point twice in different words
- Qualification stacking: "this is important because X, which in turn means Y, leading to Z" → just say Y

Read every sentence. If removing it loses no meaning, remove it.

**6. Trust the reader**

One tight sentence beats a paragraph. If it's obvious, cut it. Write for someone smart and busy who will skim.

**7. Present decisions honestly**

If genuine options exist, name them with their real trade-offs. Don't pretend a decision has been made when it hasn't — it reads as fake and invites harder questions in review. A passport that says "Option A or B, pending X decision" is more credible than one that picks arbitrarily.

**8. Surface open questions**

A section for unresolved questions is not weakness — it's what makes the document useful for alignment. Include it when the doc is seeking approval or input, not reporting a done decision.

**9. For Notion docs: create privately first**

Always create as a private workspace-level page before placing in shared spaces. Iterate and get user sign-off, then move it to the right place.

## Tone Test

Before finishing, read it aloud. Any sentence that sounds like it could be AI-generated gets cut or rewritten.

Common rewrites:

| Instead of | Write |
|---|---|
| "This solution could potentially drive significant business value" | "This drives revenue" |
| "It's important to note that..." | Just say the thing |
| "In order to ensure that..." | "To..." |
| "Moving forward, the team will..." | "Next: ..." |
| Numbered list of 6+ items | 3 tight bullets |
| "The goal of this project is to..." | Lead with the goal, no preamble |

## Common Mistakes

- **Writing before reading references** — always find real examples first
- **Symmetric sections** — not every section needs the same depth; let important things breathe, collapse obvious ones
- **Hedging to seem balanced** — it reads as weak; make a call or surface it as an open question
- **Explaining the obvious** — if a smart reader can infer it, cut it
- **Burying the dream** — the objective should be the most compelling sentence in the doc
